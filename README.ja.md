# Codex Thread Manager

[English](README.md) | 日本語

Codex Thread Managerは、現在のワークスペースに関連付けられたCodexスレッドを整理するためのVS Code拡張機能です。

現在は、個人利用向けのVSIXパッケージとして提供しています。Marketplaceへの公開は予定していません。

## 機能

- `cwd`が開いているワークスペースフォルダーと完全に一致する、アクティブおよびアーカイブ済みのCodexスレッドを一覧表示します。
- ワークスペース内でピン留めしたスレッドを専用グループにまとめます。
- Codex App Serverを通じてアクティブなスレッドの名前を変更します。
- スレッドのアーカイブ、直後の取り消し、アーカイブ済みスレッドの復元に対応します。
- 大量のスレッドをページ単位で読み込みます。
- App Serverの通知に基づいて、名前、アーカイブ状態、実行状態を更新します。
- 選択したスレッドの会話を同じCodexサイドバー内に開き、保存済みのユーザー／Codexメッセージ、ターン状態、要約された作業カードを表示します。
- 既存スレッドへテキストプロンプトを送信し、Codexの応答をその場でストリーミング表示し、必要に応じて実行中のターンを停止します。
- コンポーザーのAddメニューから、PNG、JPEG、GIF、WebP画像、ホスト側で選択したファイル参照、有効なワークスペースSkillを次のメッセージへ追加します。
- `@query`でワークスペースファイル、`$query`で有効なSkillを検索候補として表示し、キーボード、マウス、日本語IMEで操作できます。
- サイドバーからワークスペースに紐づく新しい会話を開始し、選択したRuntime設定を適用して、一覧に重複を作らず最初のテキストプロンプトを送信します。
- Runtimeトリガーに選択中のモデル、推論レベル、権限ラベルを表示し、高速サービスを選択している場合のみFastを追加します。
- 切断中も最後に確認できた会話履歴を表示し続け、再接続後に`thread/resume`と`thread/read`で再同期します。
- 一覧へ戻った際の位置を維持し、VS Codeウィンドウの再読み込み後は履歴を再取得して選択中の会話を復元します。
- PinnedとRecent threadsを初期状態で展開し、Archiveを折りたたみ、各グループの表示状態を記憶します。
- スレッドカード全体から会話を開き、ピン留め、名前変更、アーカイブ、復元をインラインアイコンで操作できます。
- ワークスペース単位で個別のターンをブックマークし、会話ヘッダーに固定されたメニューからその位置へ戻れます。
- CLIの解決結果、実行時および生成時のプロトコルバージョン、互換性診断を`Codex Thread Manager`出力チャンネルへ記録します。

ピン留めとターンのブックマークは、VS Codeの`workspaceState`に保存されます。Codex、ほかのワークスペース、ほかの端末とは同期されません。

## 必要条件

- VS Code 1.92.0以降。
- 信頼済みのローカルまたはリモートワークスペース。
- VS Code Extension Hostが動作する環境にインストールされたCodex CLI。
- そのCLIでCodexの認証が完了していること。

リポジトリに含まれるプロトコルスナップショットは、Codex CLI `0.144.2`から生成されています。バージョンが完全に一致する必要はありません。拡張機能は、必要なApp Serverメソッドとレスポンス境界の互換性を実行時に確認します。

## VSIXからインストール

個人利用向けパッケージをビルドします。

```bash
nvm use
npm run bootstrap:offline
npm run package
```

ローカルのnpmキャッシュが不足している場合は、ネットワークへ接続できる状態で`npm run bootstrap`を実行してください。

続いて、`codex-thread-manager-0.1.0.vsix`を次のいずれかの方法でインストールします。

- VS Code: **Extensions: Install from VSIX...**
- コマンドライン:

```bash
code --install-extension codex-thread-manager-0.1.0.vsix
```

インストール後にVS Codeを再読み込みしてください。

## 使い方

1. ワークスペースフォルダーを開きます。
2. アクティビティバーからCodexビューを開きます。
3. 標準の**Threads**ビュータイトルで、更新アイコンの隣にある歯車アイコンを選択して拡張機能の設定を開きます。
4. 一覧が読み込まれていない場合は、更新アイコンを選択します。
5. **New conversation**を選択し、必要に応じてRuntime設定を変更してから、最初のテキストメッセージを入力して**Send**を選択します。
6. 既存スレッドのアクションアイコン以外の場所を選択すると、保存済みの会話履歴が同じCodexサイドバー内に開きます。
7. グループ見出しを選択して、Pinned、Recent threads、Archiveを展開または折りたたみます。
8. 行へマウスカーソルを合わせるかキーボードフォーカスを移動し、インラインアイコンからピン留め、名前変更、アーカイブ、復元を行います。
9. 選択中のモデルが画像に対応している場合は、**Add** > **Add image…**から、1ファイル20 MB以下のPNG、JPEG、GIF、WebP画像を最大10件添付できます。
10. **Add** > **Mention files…**または**Add Skill…**から、ファイル参照または有効なSkillを次のメッセージへ追加します。
11. 単語境界で`@query`または`$query`を入力して、ワークスペースファイルまたは有効なSkillを検索します。上下矢印キーとEnterまたはTabを使用するか、マウスで候補を選択すると、そのクエリだけが添付チップへ変換されます。
12. テキストメッセージを入力して**Send**を選択するか、Ctrl+Enter／Cmd+Enterを押します。Enterだけを押すと改行します。
13. Codexの応答中に**Stop**を選択すると、そのターンを中断します。
14. ターンヘッダーの星アイコンでブックマークし、会話ヘッダーの**Bookmarks**メニューから選択すると、その位置へ移動します。
15. 更新アイコンで選択中の会話へ再接続して再同期し、戻るアイコンで一覧へ戻ります。
16. **View: Toggle Output**を開き、接続診断を確認するには`Codex Thread Manager`を選択します。

開いているいずれかのワークスペースフォルダーパスと`cwd`が完全に一致するスレッドだけが表示されます。ネストしたサブディレクトリで開始したスレッドは、現在のバージョンでは表示されません。

## 設定

### `codexThreadManager.codexPath`

既定値: `codex`

既定値を使用する場合、拡張機能は次の順序でCodexを解決します。

1. Extension Hostの`PATH`にあるネイティブ`codex`実行ファイル。
2. `PATH`にある公式`@openai/codex` npm shim。

Windowsでは、npmの`.cmd`および`.ps1` shimをシェル経由で起動しません。隣接する`@openai/codex`パッケージを検証し、JavaScriptエントリーポイントをNode.jsで起動します。

自動解決に失敗する場合は、ネイティブ実行ファイルまたは公式npm shimへのパスを明示的に設定してください。別のVS Code拡張機能内にあるパスは意図的に検索しません。

### `codexThreadManager.pageSize`

既定値: `50`、許容範囲: `1`〜`200`

アクティブまたはアーカイブ済みのスレッドを1ページあたり何件取得するかを指定します。

### 新しい会話の既定値

- `codexThreadManager.defaultPermission`の既定値は`auto`（**Approve for me**）です。`ask`または`full`も選択できます。
- `codexThreadManager.defaultSpeed`の既定値は`standard`です。`fast`に設定すると、使用中のモデルで利用可能な高速サービス階層を選択します。

これらの設定は、新しい会話を開いたときに適用されます。モデルと推論レベルには現在のCodex既定値が引き続き使用され、すべてのRuntime設定は新しい会話のコンポーザーから変更できます。

## Remote、WSL、コンテナー

この拡張機能はワークスペース拡張です。Remote SSH、WSL、Dev Containersでは、ローカル環境だけでなく、リモート環境内にCodex CLIをインストールして認証を完了してください。

拡張機能がローカルのApp Server子プロセスを起動する必要があるため、VS Code for the WebとVirtual Workspacesには対応していません。

## トラブルシューティング

### Codex CLIが見つからない

- 同じローカルまたはリモート環境のターミナルで`codex --version`を実行します。
- `codexThreadManager.codexPath`へネイティブ実行ファイルまたは公式npm shimを設定します。
- 出力チャンネルを確認し、Extension Hostが実際に解決したパスを確認します。

### CLIに互換性がないと表示される

実行時のCLIは生成済みプロトコルのバージョンと異なっていても構いませんが、必要な`initialize`、`thread/list`、会話用の`thread/read`境界には互換性が必要です。Codex CLIを更新するか、別のCLIパスを選択して、失敗した操作を再試行してください。

### スレッドが表示されない

- ワークスペースフォルダーが開いていることを確認します。
- スレッド作成時の`cwd`が、そのフォルダーと完全に一致していることを確認します。
- スレッドがexecまたはサブエージェントの履歴ではなく、対話型Codexスレッドであることを確認します。
- 出力チャンネルで接続エラーまたは境界検証エラーを確認します。

### リモートワークスペースへ接続できない

リモート、WSL、コンテナー環境内にCodex CLIをインストールし、認証を完了してください。リモートのExtension Hostはローカル端末のCLIを使用しません。

### アーカイブまたは名前変更に失敗する

App Serverが操作を拒否した場合、ローカルの一覧は変更されません。出力チャンネルを確認し、CLIまたは接続の問題を解決してから操作を再試行し、一覧を更新してください。

## 制限事項

- 既存および新規スレッドでは、テキスト、ローカル画像、ホスト側で選択したファイル参照、有効なSkillを入力として使用できます。構造化された`mention`入力はアプリ、コネクター、プラグイン用に予約されているため、ファイル参照は表示用プレースホルダーを含む明示的なテキストとして送信します。リモート画像URLとWebviewへ直接入力した任意のパスには対応していません。
- コマンド、ファイル変更、権限の承認、およびCodexの追加質問に対応しています。未対応のApp Serverリクエスト種別は、暗黙に承認せず拒否します。
- 標準MCPフォームの文字列、数値、真偽値、単一選択enumに対応しています。OpenAI固有フォーム、複数選択enum、URLモードのelicitationは、拒否またはキャンセルのみ可能です。
- 生の推論内容、コマンド出力、ファイル差分、ツールの引数と結果は意図的に表示しません。
- 古いターンの一部は要約履歴だけを保持していることがあり、その場合は会話ビューに表示します。
- 非常に大きな保存済み履歴は、現在1つのスナップショットとして読み込み、描画します。段階的な描画は今後のvNextフェーズで対応予定です。
- 新しい会話には最初のテキストメッセージが必要です。空のスレッド作成と複数ワークスペースルートからの選択には、まだ対応していません。
- スレッドの削除と一括操作には対応していません。
- 現在のVS Codeワークスペース外へピン留めを同期しません。
- ネストしたワークスペースの`cwd`照合には対応していません。
- VS Code for the WebとVirtual Workspaceには対応していません。
- `~/.codex`配下のファイルへ直接アクセスしません。Codexに対する変更はすべてApp Serverを使用します。

## 開発と検証

```bash
nvm use
npm run bootstrap:offline
npm run doctor
npm run verify
npm run test:vscode
npm run package
```

- `npm test`: ユニットテストと偽App Serverを使用した統合テスト。
- `npm run bootstrap:offline`: 正常な依存関係を再利用します。依存関係がない場合はローカルnpmキャッシュからインストールし、キャッシュが不足していればすぐに失敗します。
- `npm run bootstrap`: 正常な依存関係を再利用します。必要な場合は、取得の再試行回数を制限したキャッシュ優先のロック済みインストールを実行し、インストール後に正常性を確認します。
- `npm run doctor`: TypeScript、esbuild、VSCEに必要な直接依存関係のバージョンとランタイムファイルを検証します。
- `npm run verify:protocol`: 固定されたCodex CLIからApp ServerのTypeScriptプロトコルを一時ディレクトリへ再生成し、リポジトリ内のスナップショットまたは固定CLIバージョンとの差異を検出します。
- `npm run test:vscode`: VS Code 1.92.2を`.vscode-test`へダウンロードし、Extension Hostの登録テストを実行します。
- `npm run verify`: 依存関係の正常性、プロトコル差分、ユニット／統合／負荷／セキュリティテスト、Extension Host／Webviewの型チェック、lint、バンドル生成、必須VSIXファイルの検証を実行します。
- `npm run package`: 拡張機能をビルドし、ランタイムアセットを検証して、個人利用向けVSIXを生成します。

任意実行の実CLIスモークテストでは、CLIを初期化してメタデータを1件一覧表示し、一致するスレッドがある場合はそのスレッドだけを読み取って、IDと保存済みターン配列を検証します。

```powershell
$env:CODEX_SMOKE_PATH = 'C:\path\to\codex.cmd'
npm test
```

プラットフォーム別の手動検証項目については、[docs/TESTING.md](docs/TESTING.md)を参照してください。

プロトコルスナップショットを更新するには、`@openai/codex`開発依存関係のバージョンを正確に更新し、次を実行します。

```bash
npm run generate:protocol
```

依存関係、生成済みスナップショット、互換性テストの変更は、まとめてコミットしてください。
